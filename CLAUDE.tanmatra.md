# CLAUDE.md — Tanmatra (Wellness-Foods)

Persistent context for agent sessions in this repo. Read fully before the first edit of a session.
Where this file overlaps the **High-Fidelity Engineering Protocol** (`SKILL.md`), the protocol governs — this file supplies project-specific facts, laws, and targets.

---

## 1 · What this is

Tanmatra is a clinical-nutrition cloud kitchen (Noida, Delhi NCR) with a D2C storefront and subscription meal plans. Solo-founder codebase. Consumer storefront is React + `routes.ts`; kitchen/menu data syncs from Petpooja; payments via Razorpay.

**The pillar is the subscription.** À-la-carte exists to feed it. Features that don't serve the plan are parked, not built.

## 2 · Non-negotiable laws

These fail CI or fail review. No exceptions, no "just for now."

1. **One consumer design system.** `.tnm2` only on storefront routes. The shadcn-based admin system never crosses over. Legacy System-A imports on storefront routes fail CI.
2. **Zero literals in components.** No hex/rgb/hsl (stylelint gate). No `₹[0-9]` price literals. No hardcoded geography strings. Rejected named hexes include the superseded homepage palette (`#FAF8F3 #1F6B4F #DCC9A3 #2E7D32`) **and** the Stitch "Nocturnal" export palette (`#fbbf24 #f9bd22 #ffe1a7 #131313 #e2e2e2 #c6c6c7 #d3c5ac #454747 #34daff #ffb4ab`).
3. **Every numeral is JetBrains Mono** via the `tnm-data` utility with `font-variant-numeric: tabular-nums`. This is what makes digit transitions CLS-0.
4. **Standard Four states** on every data screen: default, loading, empty, error. Skeletons occupy the **exact final boxes** — nothing mounts after paint.
5. **Macros are gated on the PDP only** (behind Goal Fit). Open macro ribbons everywhere else. Never put kcal/macros in a PDP hero chip.
6. **Saffron `#E89A3E` is the sole action hue.** Caution and alert states always carry **icon + text**, never color alone.
7. **Money integrity.** No client-computed amount ever reaches an order. Server recomputes and Razorpay receives the server figure.
8. **Trust strip is one quiet line directly above Pay.** Not a section, not repeated.
9. **No cure claims.** Never treat / cure / reverse / prevent / guarantee in health copy. "Supports, doesn't replace, medical care" is the standing frame.
10. **An enabled control must do something.** Silent click absorption is a P0 class defect (it has shipped here before). Disabled states carry an explicit visible reason.

## 3 · Repo topology (verify on first run — sourced from audits, may have drifted)

- `routes.ts` — the **live route manifest**. All new screens register here.
- `App.tsx` — a **dead router**, diverged by ~15 routes. Quarantine/delete; never add to it.
- `Checkout.tsx` — ~2,599 LOC, the heaviest built asset. Refactor **inside** it; do not rewrite from scratch. Its Razorpay plumbing is load-bearing.
- `tanmatra-v2/` — `.tnm2` storefront components.
- `StitchClinicalOverview.tsx` — stranded, unwired. Wired-or-deleted rule applies.
- Prerender list is missing transactional routes → cold-load blank screens on `/cart`, `/checkout`, `/subscribe`, `/dish/*`.

**Start every session by verifying these against the actual tree.** Report drift rather than assuming.

## 5 · Working agreement

- **One task brief per session.** Briefs live in `tasks/`. Do not merge scope across briefs.
- **Blast radius calibration.** Money path (`/cart`, `/checkout`, order creation) and anything allergen- or dose-related is maximum rigor: read before write, test the failure mode, no speculative refactors. Marketing surfaces are low blast radius.
- **Never touch parked scope.** Wellness tracker, RD partner funnel, corporate/B2B, kitchen ERP, admin consoles — designed but parked. Building them is out of scope even if a design exists.
- **Prototype literals are not production values.** Everything marked `PROTO` or `[quote]` binds to real sources. Only ₹155 (Almond Chicken Salad) is live-verified.
- **Third-party failure modes are yours.** Razorpay, Petpooja, and any Google/Stitch endpoint fail, rate-limit, and return partial data. Handle it explicitly; never assume the happy path.
- **Stop and ask** before: schema migrations, changing tax logic, altering Razorpay flow beyond the brief, deleting anything outside a brief's file list, or resolving open decisions D2–D5 from Checklist v1.2.

## 6 · Verification (run before declaring done)

```bash
npm run lint          # includes token/literal gates
npm run typecheck
npm run test
npm run test:e2e      # Playwright: price authority, CLS, checkout states
```

Plus the brief's own acceptance criteria. **A task is done when its checks pass, not when the code looks right.**

## 7 · Commit & PR discipline

- Small, single-purpose commits; imperative subject; body states *why*.
- One PR per task brief. PR description = brief objective + acceptance checklist with results.
- Never force-push shared branches. Never commit secrets, `.env`, or API keys.
- If a brief turns out to be wrong or under-specified, say so in the PR and stop — don't improvise scope.
